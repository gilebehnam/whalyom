## Email, deliverability and messaging

- **Gmail BIMI (Google Workspace Admin Help): to show a brand logo, the domain's DMARC policy must be p=quarantine or p=reject with pct=100 (p=none isn't supported), and you need a Verified Mark Certificate (VMC, needs a trademarked logo, can take 6-12 months) or a Common Mark Certificate (CMC). The logo must be SVG Tiny PS (baseProfile tiny-ps, version 1.2), at least 96x96 px with absolute size, delivered in a PEM file. Only VMC senders get Gmail's checkmark.** (2026-11-03; official, high) [source](https://knowledge.workspace.google.com/admin/security/set-up-bimi?hl=en) `K-06dc06f5ae`
- **Apple Mail Privacy Protection ('Protect Mail Activity' in Mail settings) hides the recipient's IP address and downloads remote content privately in the background when a message arrives, not when it is opened. Senders therefore can't learn whether or when a message was opened. Treat open rates from Apple Mail users as inflated and unreliable: don't use opens for A/B winners, engagement-based sunsetting or send-time optimisation. Use clicks, replies and conversions instead.** (2026-11-03; official, medium) [source](https://support.apple.com/guide/mail/protect-email-privacy-mlhlp1205/mac) `K-40e9f4674d`
- **Gmail Postmaster Tools lets verified domain owners report a delivery issue (Report delivery issue, bottom left). The domain must meet Google's sender guidelines, and the message you report must pass both DKIM and SPF with a From: header domain matching the domain you send from. Fix authentication and compliance before using this route.** (2026-11-03; official, high) [source](https://support.google.com/mail/answer/16740603?hl=en) `K-752658ec5f`
- **Google's recommended DMARC rollout: set up SPF and DKIM at least 48 hours before DMARC. Start with p=none for one week and review the reports daily. If outgoing mail shows no problems, quarantine a small share of messages (large organizations can start at 1%) and raise the percentage gradually to 100%. Use p=reject only if needed, because failing mail is then never delivered. Move to enforcement this way before applying for BIMI, which needs quarantine or reject at 100%.** (2026-11-03; official, high) [source](https://knowledge.workspace.google.com/admin/security/recommended-dmarc-rollout?hl=en) `K-d5d0547988`
- **Gmail Postmaster Tools v2 has a Compliance status dashboard. For all senders it checks SPF, DKIM, DNS records, formatting, encryption and the user-reported spam rate. For bulk senders (about 5,000+ messages to Gmail in 24 hours) it also checks DMARC, one-click unsubscribe and whether unsubscribes are honored within 48 hours. Status reads Compliant, Needs work or No data found, for primary domains and personal Gmail traffic only. Data usually updates within 24 hours, but fixes can take up to 7 days to show.** (2026-11-03; official, high) [source](https://support.google.com/a/answer/14668346?hl=en) `K-d98c75f630`
- **Gmail's sender guidelines say: use a consistent From: address for each message category (for example sales receipts, promotions, account alerts). Ideally send from one IP; if you use several, assign a different IP to each message type. Don't mix content types, such as promotions inside receipts. New senders should start with low volume to engaged users and increase slowly, avoiding sudden spikes. Don't impersonate Gmail From: headers: Gmail is moving toward DMARC quarantine enforcement for them.** (2026-11-03; official, high) [source](https://support.google.com/mail/answer/81126?hl=en) `K-dc38d1ef69`
- **Microsoft's outbound best practices for mail to Microsoft 365: the sending domain must resolve in DNS, or mail goes via the high-risk delivery pool. The IP needs a reverse DNS (PTR) record. HELO/EHLO and MAIL FROM should use a consistent domain name matching rDNS, not an IP. Publish SPF, sign DKIM with relaxed header canonicalization, keep WHOIS accurate, format bounces per RFC 3464, remove addresses that hard-bounce, and monitor IPs in Outlook.com SNDS.** (2026-07-24; official, high) [source](https://learn.microsoft.com/en-us/defender-office-365/anti-spam-protection-faq) `K-96698adc06`
- **Microsoft 365 business mailboxes give every inbound message a bulk complaint level (BCL) from 0 to 9. At or above the tenant's threshold, newsletters and promotions are treated as Bulk and by default go to Junk, even when recipients opted in. Some tenants can send bulk mail below the threshold to a Promotions folder (preview). B2B senders can't change a recipient's threshold: keep complaints low, send only to engaged contacts, and ask key accounts to add you to Safe Senders.** (2026-07-24; official, high) [source](https://learn.microsoft.com/en-us/defender-office-365/anti-spam-protection-faq) `K-ccb72e1b55`

## Privacy, consent and data law

- **Connecticut Data Privacy Act (AG guidance): it applies to controllers processing data of 35,000+ consumers, to anyone processing sensitive data or selling personal data, and to all consumer health data controllers. Since 1 Jan 2025, every covered controller must honor opt-out preference signals such as Global Privacy Control for targeted ads and sales. Sensitive data needs consent. Selling data of, or targeting ads to, consumers under 16 needs opt-in consent, and online services may not target ads to known minors under 18. Profiling needs an impact assessment.** (2026-11-03; official, medium) [source](https://portal.ct.gov/ag/sections/privacy/the-connecticut-data-privacy-act) `K-db9a4b5319`

## Analytics, tracking and measurement

- **Consent mode implementation: call gtag('consent','default',...) on every page before any config or event command, since out-of-order code breaks defaults. Use wait_for_update (e.g. 500 ms) when the CMP loads asynchronously; set region-specific defaults with ISO 3166-2 codes (US-CA overrides US; a default without region covers everyone else); send gtag('consent','update',...) as soon as the user chooses and persist the choice in a first-party cookie.** (2026-11-03; official, high) [source](https://developers.google.com/tag-platform/security/guides/consent) `K-0f5c3b780a`
- **GA4 standard property configuration limits: 50 event-scoped custom dimensions, 25 user-scoped custom dimensions, 50 event-scoped custom metrics, 30 key events, 100 audiences, 50 custom insights, 200 explorations per user (500 shared), 400 Ads links, and 10M events per exploration query. Analytics blocks new items once a limit is reached, so budget custom dimensions in the tracking plan and archive unused ones.** (2026-11-03; official, high) [source](https://support.google.com/analytics/answer/12229528?hl=en) `K-1317b85450`
- **Basic vs advanced consent mode: basic blocks Google tags until the user interacts with the banner and sends nothing (not even consent state) if consent is denied, so Ads conversion modelling uses a general model. Advanced loads tags with consent defaulted to denied and sends cookieless pings, enabling an advertiser-specific model once a data threshold is met. Choose per the company's legal position; advanced recovers more modelled conversions.** (2026-11-03; official, high) [source](https://developers.google.com/tag-platform/security/concepts/consent-mode) `K-1aab001f7d`
- **GA4 Measurement Protocol sends server-to-server and offline events over HTTP, but it is meant to augment gtag, Tag Manager or Firebase collection, not replace it; a tagging method must already be in place. Join events to users with client_id (web) or app_instance_id (app), include session_id within 24 hours to attach session geo and device data, and test payloads against the validation server first.** (2026-11-03; official, high) [source](https://developers.google.com/analytics/devguides/collection/protocol/ga4) `K-71e291eb75`
- **Server-side Google Tag Manager runs a server container you control: clients (built-in GA4 and Measurement Protocol) claim incoming requests and turn them into events, then sandboxed tags with permissions forward data to vendors. You decide what data leaves and where it goes; Google recommends serving the container from a first-party subdomain before production traffic. Host on your own Google Cloud project or manually elsewhere. It does not remove consent obligations.** (2026-11-03; official, high) [source](https://developers.google.com/tag-platform/tag-manager/server-side/intro) `K-79278cd794`
- **GA4 standard event collection limits: event names max 40 characters; 25 parameters per event (ecommerce events can add up to 27 item-level custom parameters); parameter names 40 chars and values 100 chars (page_title 300, page_referrer 420, page_location 1,000); 25 user properties (names 24, values 36 chars); app streams max 500 distinct event names per user, web streams unlimited. Character limits do not rise with GA4 360, so keep tracking-plan names short.** (2026-11-03; official, high) [source](https://support.google.com/analytics/answer/9267744?hl=en) `K-975cd0ff75`
- **Meta Pixel + Conversions API deduplication: Meta recommends a redundant setup sending the same events from browser and server. Give each event the same id in both (Pixel eventID as the 4th fbq argument = server event_id) and the same event name; Meta keeps one, generally the first received. Dedup only works within 48 hours of the first event with that id. The fallback (same event_name plus fbp and/or external_id) works only when the browser event arrives first.** (2026-11-03; official, high) [source](https://developers.facebook.com/docs/marketing-api/conversions-api/deduplicate-pixel-and-server-events) `K-c893a85124`
- **GA4 data retention: standard properties can keep user- and event-level data 2 or 14 months; 360 can keep event data 2, 14, 26, 38 or 50 months (user-level 2 or 14). Retention affects only explorations and funnel reports, not standard aggregated reports. Age, gender and interest data is always 2 months. Set 14 months at setup, keep 'reset on new activity' on, and export to BigQuery for longer history needed by cohort or MMM work.** (2026-11-03; official, high) [source](https://support.google.com/analytics/answer/7667196?hl=en) `K-f512726fdf`
- **GA4 changes in 2026: custom conversion windows (engaged-view 1-30 days, previously fixed at 3; click-through 1-90 days) from 11 Aug 2026. A currency field is required for campaign cost data imports from 28 Jul 2026. Dashboards launched 9 Sep 2026. Hostname Include filters (allowlists) arrived 21 Sep 2026. A Source Group dimension (consolidating sources like Facebook, Instagram, TikTok) arrived 11 Jun 2026.** (2026-10-05; official, high) [source](https://support.google.com/analytics/answer/9164320?hl=en) `K-9ac72c39db`
